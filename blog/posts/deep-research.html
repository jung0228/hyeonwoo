Deep Research란 무엇인가

사람이 주제를 조사하는 과정 — 질문을 쪼개고 → 검색하고 → 읽다가 모르면 또 검색하고 → 출처를 비교해 → 보고서를 쓴다. 이 루프를 LLM이 자동으로 수행하게 만든 것이 Deep Research다.

정의agent가 능동적으로 planning · retrieval · synthesis에 관여해, 웹 근거에 기반한 충실한(faithful) 분석 리포트를 생성하는 패러다임 (Survey 2025)
왜 — 추론모델o1/o3·R1 같은 reasoning model이 긴 사고사슬을 안정적으로 굴리며 "생각하다 검색하고 또 생각하는" 루프가 실용화
왜 — scalingtest-time scaling: 추론 시점에 연산(생각·검색)을 더 쓸수록 어려운 문제가 풀린다 → 그 "더 오래 일하기"를 검색에 적용
왜 — 제품화OpenAI Deep Research, Gemini Deep Research, Perplexity Deep Research가 2025년 연이어 등장하며 분야로 정착
출처: Deep Research Survey (arXiv:2508.12752)03 / 13

RAG · Web agent와 무엇이 다른가

가장 헷갈리는 구분. 핵심은 "검색이 추론과 얽혀 동적으로 반복되느냐" — 이걸 agentic search 또는 reason-in-search라 한다.

한 줄 정의검색 횟수추론산출물
RAG (전통)질문 → 한 번 검색 → 그 문서로 답보통 1회거의 없음짧은 답
Web agent웹에서 클릭·입력 등 행동(action)으로 과제 수행다회(행동)중간과제 완료(예약 등)
Deep Research추론 도중 필요할 때마다 반복 검색 + 종합다회·동적핵심긴 리포트 / 검증된 정답

한 번 도는 과정 — 4단계 파이프라인

핵심은 ③ web exploration이 한 번이 아니라 루프라는 것. 읽다가 지식 공백이 보이면 다시 쿼리를 만들어 또 검색한다. 이 "스스로 공백을 메우는 반복"이 Deep Research의 정체성.

① planning질문을 하위 과제로 분해하고 조사 계획 수립
② question dev각 하위 과제를 구체적 검색 쿼리로 변환
③ web exploration검색 → 열람 → 읽기 → 추출, 공백 발견 시 ①/②로 되돌아가 반복
④ report gen근거를 종합·교차검증해 리포트(또는 정답) 작성 + 인용
출처: Deep Research Survey (arXiv:2508.12752)05 / 13

워크스루 — 안에서 무슨 일이 벌어지나

예시 질문: "최근 3년간 on-device LLM 추론 가속 기법들을 비교 정리해줘." 4단계가 실제로 어떻게 도는지 따라가 본다.

  • ① Planning — 과제를 쪼갠다: (a) quantization, (b) KV cache 최적화, (c) speculative decoding, (d) 하드웨어(NPU) 측면.
  • ② Question developing — 각각을 쿼리로: "LLM 4-bit quantization 2024 survey", "KV cache compression on-device" …
  • ③ Web exploration ↻ — 검색·논문 열람·수치 추출. (b)를 읽다 "sliding-window attention과의 관계가 빠졌네" → 새 쿼리로 다시 검색(루프).
  • ④ Report generation — 4개 축으로 표를 만들고, 출처를 달고, 트레이드오프를 종합 → 리포트.

능력 3축 프레임 — 이 분야를 보는 척추

Deep Research agent가 잘해야 하는 능력은 찾기 · 풀기 · 쓰기 3축 + 가로축 사실성으로 갈린다. 벤치마크도 이 축을 따라 설계된다 — "어느 축을 공략하는 논문/벤치인가"로 보면 정리된다.

벤치마크 지도

단일 canonical 벤치는 아직 없다. 논문마다 "찾기용 + 풀기용 + 쓰기용"을 골라 조합한다. 주 측정 축으로 정리하면:

벤치마크주 축답 형식한 줄
HotpotQA · 2Wiki · MuSiQue찾기(+추론)단답RL-search 논문의 표준 체급 측정용 multi-hop QA
GAIA찾기+풀기+tool단답466문항·3난도. 사람 92% vs GPT-4+plugin 15%. assistant 기준점
FRAMES셋 다단답824 multi-hop, 2~15개 위키 통합. single 0.40 → multi 0.66
BrowseComp찾기(극악)짧은 단답"풀긴 어렵고 검증은 쉽게". LLM이 CORRECT/INCORRECT 판정
HLE풀기(극악)MC/단답2,500문항·100+분야. 빠른 검색으론 안 풀리는 끝판 변별
DeepResearch Bench쓰기/종합장문 리포트100 PhD급 과제. RACE 프레임으로 4차원 채점

어떻게 채점하나 — 3가지 방식

"평가"가 추상적으로 들리지만, 실제론 답 형식에 따라 채점 방식이 정해진다. 단답이면 매칭, 장문이면 LLM이 심사, 인용은 따로 검증.

  • ① Exact / fuzzy match — 정답 문자열과 비교(단답 벤치). 가장 객관적, 단답에만 가능. 예: 정답 "1923" → 모델 "1923년" → 정답 처리
  • ② LLM-as-judge — 강한 LLM이 채점. BrowseComp: 모델 답 vs 정답 → CORRECT/INCORRECT 이진. DeepResearch Bench(RACE): 포괄성·깊이·지시준수·가독성 4차원 점수.
  • ③ Factuality / citation 검증 — 리포트의 각 주장이 인용 출처에 실제로 근거하는지 확인. hallucination·허위인용 잡기.
  • 채점 예시 (BrowseComp식) — 답이 짧아 "쓰기"가 안 섞임 → 모델이 "<논문 제목> (confidence 0.7)" 출력 → judge가 정답과 대조 → CORRECT. 순수 "찾기"만 측정.

대표 논문 계보

"검색하는 LLM"의 뿌리 → reasoning model 시대 → 검색을 RL로 훈련 → 계획·탐색·리포트까지 하는 본격 agent. 시대순으로.

뿌리 — 검색하는 LLM (2021–2023)
WebGPT · ReAct · Toolformer브라우저 검색+인용 / reasoning↔acting / API 호출 학습 — agentic search의 원형
Self-RAG · FLARE언제·무엇을 검색할지 스스로 제어, 생성 도중 능동 검색
reasoning model 시대 — agentic RAG (2025)
Search-o1o1류 LRM + agentic RAG — 추론 중간에 검색을 끼워 넣는 reason-in-search
RL for search (2025)
Search-R1 · R1-Searcher검색 호출을 RL로 훈련(outcome reward). Search-R1 +41%(Qwen2.5-7B)
본격 deep research agent (2025)
WebThinker · STORMThink-Search-Draft로 리포트까지 / 다관점 질문으로 위키식 장문 작성

방법론 패러다임 — 어떻게 만드나

크게 세 갈래. 실무에선 섞어 쓴다 — RL로 검색을 키운 모델을 framework 안에 넣고 prompting으로 흐름을 제어.

패러다임방식장점단점
Prompting / agentic-RAG학습 없이 프롬프트·스캐폴딩으로 검색 루프 구성 (Search-o1)빠르고 모델 안 건드림검색 타이밍·품질 불안정
RL for search검색 호출을 RL로 훈련 (Search-R1, R1-Searcher)검색을 "잘" 쓰게 내재화, 성능↑학습 비용·실웹 환경 구축
Framework / multi-agentplanner·searcher·writer 분업 (STORM, GPT-Researcher)모듈화·긴 리포트에 강함오케스트레이션 복잡, 오류 전파
